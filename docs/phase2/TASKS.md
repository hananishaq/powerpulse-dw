## Order of work

1. **Everyone, first:** install PostgreSQL 16+ (with pgAdmin) and Python 3.10+, clone the repo, create `.venv`, `pip install -r requirements.txt`.
2. **Step 1 owner pushes the setup scripts first** (about 30 minutes of work). Everyone then runs them to get their own local database.
3. **Steps 2, 3, 4, 5A start at the same time.** The design is already fixed by Phase 1, so you can write your SQL against the names in the contract below without waiting for each other. You can only *test* once the step before yours has pushed.
4. **Hand-off order for testing:** 2 → 3 → 4 → 5A, then the Step 1 owner finishes the reporting views.
5. Step 1 owner runs the whole thing from scratch on a clean database, then tags `phase2-submission`.

> **Git shares scripts, not databases.** Every teammate runs the numbered SQL scripts to build their own local copy of `powerpulse_dw`.
> If a script works on your machine but not on a teammate's, the script is wrong. Fix the script, not the database.

## Team workflow

- `git pull` before you start and before you push. Commit small and often: `git commit -m "staging: add clean table"`.
- Work on a branch named after your step (`git checkout -b step2-staging`), push it, and merge it on GitHub with a pull request. Another teammate glances at it first.
- Never edit another person's folder. If you need something changed, message the owner.
- **Never commit passwords.** Your DB password lives only in `.env`, which is git-ignored. This repo is public.
- Tick the boxes below when a task is merged, not when it is "almost done".
